# ТЗ (финальное, самодостаточное): UI/UX-редизайн Личного Кабинета в стиле Claude.ai

Версия для передачи в Google Antigravity. Документ объединяет дизайн-систему (палитра, типографика,
Theme Engine) и структуру/процесс редизайна (карта экранов, компоненты, релиз) в единый файл.
Дополнительно приложены скриншоты интерфейса Claude.ai как визуальный референс (см. раздел 1.1).

---

## 0. Контекст и границы документа

Документ описывает ТОЛЬКО визуальный и интерфейсный слой (presentation layer) уже реализованной системы
KRB SaaS MVP. Backend, API-контракты, база данных, RAG-логика, авторизация, 2FA, шифрование ключей —
остаются без изменений. Функциональные требования — по TZ_LK_RAG_arhitektura.md, реализованный
функционал — по TECHNICAL_SPECIFICATION.md.

Главный принцип: экраны обращаются к дизайн-системе за визуальными компонентами, но дизайн-система
не знает и не должна знать ничего про бизнес-логику, API-вызовы, роли пользователей или данные RAG.

---

## 1. Философия дизайна (для Antigravity)

- Документ, а не "SaaS-дэшборд": много воздуха, минимум декоративных элементов, нет градиентов и
  тяжёлых теней.
- Тёплый нейтральный фон вместо холодного белого/серого — ощущение бумаги, а не экрана.
- Один акцентный цвет (терракотовый/коралловый по умолчанию), используемый точечно — для CTA и
  ключевых состояний.
- Контраст через типографику (крупный serif-заголовок + нейтральный sans-body), а не через цвет.
- Плоская архитектура компонентов: границы вместо теней, скругления умеренные (8-16px).
- Все цвета — переменные (токены), а не константы: компонент не знает конкретный HEX, только имя токена.

### 1.1 Визуальные референсы (приложены скриншоты Claude.ai)

При реализации ориентироваться на приложенные скриншоты интерфейса Claude.ai:
- Список карточек (Projects) — плоские карточки с тонким border, без тени, умеренный radius, дата
  вторичным серым текстом внутри карточки.
- Пустой экран нового чата (New chat) — крупное приветствие serif-шрифтом с эмодзи-акцентом, центрированное
  поле ввода, набор быстрых action-кнопок (pill-стиль) под полем.
- Экран диалога — сообщение пользователя оформлено как компактная серая капсула справа, без "речевого
  пузыря" с хвостиком; ответ ассистента — обычный текст без обёртки, слева.
- Детальная страница проекта — двухколоночный layout: контент слева, правая узкая панель с блоками
  Memory / Instructions / Files, разделёнными тонкими горизонтальными линиями, без карточек-теней.
- Индикатор использования (Files, "% of project capacity used") — тонкий линейный прогресс-бар,
  акцентный цвет заполнения, процент — текстом рядом.

Важно: это референс на дух и паттерны компоновки, не на буквальное копирование бренда, лейблов или
логотипа Anthropic (см. п.10 "Что не копировать").

## 2. Архитектурное решение (зафиксировано на этапе планирования)

- Дизайн-система реализуется как отдельная папка внутри существующего проекта `/client`
  (`/client/src/design-system`), без выделения в отдельный npm-пакет — решение принято исходя из
  скорости запуска MVP.
- Правило импортов (обязательно для code-review): компоненты экранов (`ChatWindow`, `FileLibrary`,
  `AdminPanel` и т.д.) могут импортировать компоненты из `design-system`. Обратный импорт запрещён —
  `design-system` не может импортировать ничего из `screens`, `hooks`, `api`, `store`.
- Дизайн-система не содержит: вызовов API, знания о ролях (ADMIN/CLIENT), ссылок на client_id/bot_id,
  бизнес-текстов (кроме нейтральных лейблов типа "Отправить", "Отмена").
- Будущий лендинг (Фаза 2, вне рамок этого ТЗ) реализуется отдельным проектом; переиспользование
  токенов дизайн-системы — вручную копированием значений, без общего пакета на данном этапе.
- Theme Engine (управление цветовой гаммой из админки) — надстройка над той же дизайн-системой: токены
  хранятся в БД, применяются как CSS variables в рантайме, дизайн-система читает переменные, но не
  знает механизм их обновления.

## 4. Типографика

| Роль | Гарнитура | Fallback | Особенности |
|---|---|---|---|
| Заголовки (H1-H2) | Slab-serif (тип Copernicus/Tiempos Headline) | Georgia, EB Garamond | tracking -1.5px, line-height 1.1 |
| Body / UI | Гуманистический sans (тип StyreneB) | Inter, Arial, system-ui | line-height 1.5-1.6 |
| Мета-данные, код | Monospace | JetBrains Mono, SF Mono | для timestamps, ID, кода |

Текст никогда не абсолютно чёрный — тёплый near-black по умолчанию. Обязательная иерархия: минимум
4 уровня размеров (H1, H2, Body, Caption).

## 5. Иконография

- Line-icons (Lucide / Feather-style), толщина линии 1.5-2px, без заливки.
- Единый размер сетки (20px/24px), скруглённые углы.
- Иконки используют color-text-secondary в покое, color-accent-primary — при активном/hover
  состоянии (через токен, не HEX).
- Каждая icon-only кнопка (без текстового лейбла) обязана иметь aria-label — обязательное требование
  для админ-панели и панели логов, где много icon-only действий.

## 6. Motion (анимации и переходы)

- Переходы hover/active/focus — 150-200ms, ease-in-out.
- Skeleton-загрузка — пульсирующая анимация плейсхолдеров (opacity 0.5 → 1 → 0.5), цикл ~1.5s.
- Модальные окна — fade + лёгкий scale (0.98 → 1) при открытии, длительность 200ms.
- Toast-уведомления — slide-in снизу или справа, автоскрытие через 3-4 секунды.
- Никаких resize-анимаций контента при загрузке данных (layout shift запрещён) — использовать
  skeleton точного размера итогового блока.

## 7. Компоненты дизайн-системы: структура и контракты

```
design-system/
  tokens/          — цвета, типографика, spacing, radius, motion
  primitives/       — Button, Input, Card, Modal, Badge, Avatar, Tooltip, ProgressBar
  patterns/         — EmptyState, ErrorState, LoadingSkeleton, ConfirmDialog, Toast
  layout/           — PageShell, Sidebar, TopNav, ContentContainer, TwoColumnLayout
  theme-provider/    — чтение CSS variables из API темы (см. Theme Engine, раздел 13)
```

### 7.1 Контракты базовых примитивов (props)

| Компонент | Обязательные props | Опциональные props |
|---|---|---|
| Button | variant (primary/secondary/ghost), children | size (sm/md/lg), disabled, icon, aria-label (если icon-only) |
| Input | value, onChange | placeholder, error, disabled, type |
| Card | children | padding, onClick (если интерактивная) |
| Modal | isOpen, onClose, children | title, size |
| Badge | label, status (success/error/warning/neutral) | icon |
| ProgressBar | value (0-100) | label, showPercentage |
| Toast | message, type (success/error/info) | duration |

Правило приёмки: каждый примитив документируется отдельной демо-страницей (Storybook или аналог) с
примерами всех состояний (default, hover, disabled, error) до интеграции в реальные экраны.

## 9. Детальные требования по экранам

### 9.1 Авторизация
- Форма логина: минималистичная карточка по центру, serif-заголовок, поля Input из design-system.
- Экран ввода 2FA-кода: 6 отдельных ячеек ввода кода, автопереход между ячейками.
- Ошибки авторизации — inline-текст под полем (color-error), не модальное окно.

### 9.2 Навигационная шапка
- Три переключателя (Админка / Библиотека бизнеса / Чат) — текстовые табы или pill-навигация,
  активный таб выделяется через color-accent-primary, без ярких заливок.
- Видимость раздела "Админка" — только для роли ADMIN (логика видимости не меняется, меняется вид).

### 9.3 Чат с ассистентом
- Пустое состояние (нет активного диалога) — крупное serif-приветствие + центрированное поле ввода +
  быстрые action-кнопки (по референсу New Chat, см. п.1.1).
- Выбор бота — dropdown или горизонтальный список карточек, плоские, с border.
- Сообщение пользователя — компактная капсула, выровнена по правому краю, tint-фон, без "хвостика"
  (по референсу диалога Claude, см. п.1.1).
- Ответ ассистента — обычный текст на surface-фоне без обёртки, слева.
- Grounding-источники — компактный список ссылок под ответом, вторичным текстовым стилем.
- Состояние загрузки — skeleton-анимация точного размера ожидаемого блока, не спиннер.
- Состояние ошибки — inline-сообщение в чате с кнопкой retry.

### 9.4 Библиотека бизнеса
- Древовидная структура папок — слева, sidebar-стиль, сворачиваемые узлы.
- Список файлов — карточки/таблица со статус-индикатором (Badge: готов/индексируется/ошибка).
- Drag-and-drop зона — пунктирная граница color-border, tint при наведении.
- Ошибка индексации — явный текст причины + кнопка "Повторить попытку".
- Удаление файла — обязательное подтверждение через ConfirmDialog.
- Индикатор использования хранилища — линейный ProgressBar (по референсу "% of project capacity
  used", см. п.1.1).

### 9.5 Админ-панель (общие требования для всех вкладок)
- Единый layout: боковое меню вкладок слева (API-ключи, Боты, Память, Лимиты, Диагностика,
  Оформление), контент справа.
- Двухколоночный вариант для детальных страниц (контент + правая узкая панель метаданных) —
  по референсу страницы проекта (см. п.1.1).
- API-ключи — маскированное отображение ("sk-•••••••••1234"), полная замена вместо "показать".
- Диагностика/Логи — таблица с фильтрами по уровню (ALL/INFO/ERROR/DEBUG), monospace для текста
  логов, индикатор "обновлено N секунд назад".

### 9.6 Модальные окна
- ConfirmDialog и AlertDialog — карточка по центру, backdrop с легким затемнением (без blur —
  плоский стиль, не glassmorphism).
- Анимация открытия — fade + scale (см. раздел 6).
- Закрытие по Escape и клику вне окна — сохраняется как есть.

### 9.7 Раздел "Оформление" (Theme Engine) — см. полную спецификацию в разделе 13.

## 10. Что НЕ копировать буквально

- Не использовать логотип, название или фирменные текстовые элементы Anthropic/Claude.
- Не воспроизводить точный копирайтинг интерфейса Claude.ai.
- Значения палитры по умолчанию (раздел 3) — стартовая точка, а не обязательство; бренд-цвет
  полностью настраивается через Theme Engine.

## 11. Состояния интерфейса (обязательны для каждого экрана с данными)

| Состояние | Требование |
|---|---|
| Загрузка (loading) | Skeleton-плейсхолдеры точного размера контента — не спиннер на весь экран |
| Пустое состояние (empty) | Нейтральная иллюстрация/иконка + краткий текст + CTA, если применимо |
| Ошибка (error) | Явный текст причины, кнопка повторной попытки где технически возможно |
| Успех (success) | Toast-уведомление в углу экрана, автоскрытие через 3-4 секунды |

## 12. Адаптивность

- Основной таргет MVP — desktop (1280px+), продукт B2B/профессиональный инструмент.
- Минимальная адаптивность для планшета (768px+) — сайдбар сворачивается в иконки/гамбургер-меню.
- Мобильная версия — вне рамок MVP, закладывается в CSS-архитектуру (relative units, flex/grid),

## 13. Управление цветовой гаммой из админки (Theme Engine)

### 13.1 Принцип
Компоненты обращаются к токенам по имени (--color-accent-primary), значения токенов хранятся в БД/JSON
и подтягиваются в CSS variables на рантайме. Смена гаммы = запись новых значений в БД, без релиза кода.

### 13.2 Архитектура
- Источник правды: таблица theme_tokens (или JSON-документ): {token_name, value, category, editable,
  description}.
- На фронте — CSS custom properties (:root { --color-bg: value; ... }), генерируемые из таблицы при
  загрузке.
- Theme Provider (React Context / CSS-injection) — единая точка чтения токенов всеми компонентами.
- При сохранении в админке токены пишутся в БД и инвалидируют кэш темы (применение без деплоя).

### 13.3 Функциональность экрана "Оформление"
- Цветовые пикеры для каждого editable-токена с текущим значением и превью.
- Готовые preset-темы (Light / Dark / кастомная), клонирование пресета как основы.
- Live-preview на тестовой мини-странице до сохранения — без влияния на прод.
- Автопроверка контраста WCAG AA при сохранении — предупреждение/блокировка при недостаточном
  контрасте.
- Автогенерация hover/active/disabled через HSL-модификацию базового акцента.
- История изменений с возможностью rollback на предыдущую версию.
- Экспорт/импорт темы в JSON — перенос между окружениями.

### 13.4 Технические требования к Antigravity
- API: GET /theme, PUT /theme, GET /theme/history, POST /theme/rollback.
- Валидация на бэкенде: формат HEX/HSL, обязательные поля, контраст-чек перед сохранением.
- Кэширование темы с инвалидацией при обновлении.
- Права доступа: изменение темы — только роли Admin/Owner.

### 13.5 Фаза 2 (опционально, вне первого релиза)
- Расширение админки на токены типографики, radius и spacing-scale — не включать в MVP.

## 14. Стратегия релиза

**Выбран вариант А — Hard cutover.** Так как реальных пользователей на продукте пока нет (MVP
только готовится к запуску), редизайн внедряется полным переключением: старый визуальный слой
(Tailwind dark/glassmorphism) полностью заменяется новым без необходимости держать два набора стилей
параллельно или использовать feature flag. Это сокращает объём работы и ускоряет запуск MVP.

---

## 15. Нефункциональные требования

- Отсутствие прямых HEX/цветовых констант в коде компонентов — только переменные из
  design-system/tokens.
- Все интерактивные элементы — доступны с клавиатуры (Tab-навигация, видимый focus-ring).
- Каждая icon-only кнопка — обязательный aria-label (см. раздел 5).
- Время до первой отрисовки интерфейса (FCP) — не должно деградировать относительно текущей
  реализации (контроль через Lighthouse до/после).
- Совместимость с существующим `.agents/workflows/testing_protocol.md` — редизайн не должен нарушать
  5 шагов регламента (навигация, авторизация, RAG, чат, логирование).
- Визуальная регрессия (снапшот-тестирование компонентов) и расширенный чек-лист accessibility —
  статус Should-have, не блокируют релиз MVP, могут быть добавлены как техдолг после запуска.

## 16. Критерии приёмки

### Must-have (блокируют релиз)
- [ ] Чистота архитектурных границ — ни один компонент в `design-system/` не импортирует
  бизнес-логику (`api`, `hooks`, `store`).
- [ ] Токенизация цвета — ни один экран не использует прямой HEX-цвет в коде, только переменные.

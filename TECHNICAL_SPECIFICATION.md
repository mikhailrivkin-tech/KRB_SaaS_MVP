# Техническое Задание (ТЗ) и Полное Описание Реализованной Функциональности KRB SaaS MVP

## 1. Общие Сведения о Проекте

**KRB SaaS MVP** — это корпоративная SaaS-платформа для управления базами знаний предприятия (RAG — Retrieval-Augmented Generation), автоматизации работы с документами через Google Gemini File Search Store и предоставления клиентам мульти-ассистентного ИИ-чата.

---

## 2. Архитектура Системы и Технологический Стек

### Frontend (`/client`)
- **Фреймворк**: React 18 + Vite
- **Стилизация**: Tailwind CSS (sleek dark mode, glassmorphism, градиенты, адаптивные лейауты)
- **Иконки**: Lucide React
- **Сборщик**: Vite (производственная сборка в `client/dist`)

### Backend (`/server`)
- **Среда выполнения**: Node.js + TypeScript (`ts-node` для разработки, tsc для билда)
- **Веб-сервер**: Express.js
- **ORM / База данных**: Prisma ORM + SQLite (`server/prisma/dev.db`)
- **Интеграция ИИ**: Google GenAI SDK (`@google/genai` v1beta) + Direct REST API Google Gemini

## 3. Подробный Реестр Реализованного Функционала

### 3.1. Безопасность и Аутентификация
1. **Двухуровневая модель ролей (RBAC)**:
   - `ADMIN` (Администратор платформы): полный доступ к управлению API-ключами, настройками контекста, ассистентами, клиентами, логами и RAG-библиотекой.
   - `CLIENT` (Клиент / Пользователь): доступ к разрешенным ботам и собственной персональной библиотеке знаний.
2. **JWT-авторизация**:
   - Выдача JWT-токенов при успешной авторизации (`expiresIn: 7d`).
   - Защита всех API-маршрутов с помощью middleware `authenticateToken` и `requireAdmin`.
3. **Двухфакторная аутентификация (2FA / TOTP)**:
   - Генерация секретного ключа и QR-кода для мобильных приложений (Google Authenticator, Яндекс Ключ и др.).
   - Проверка 6-значных динамических одноразовых кодов (TOTP) при входе администратора.
   - Возможность включения/отключения 2FA в панели администратора.
4. **Шифрование API-ключей**:
   - Безопасное хранение Google Gemini API ключей с использованием алгоритма шифрования `AES-256-CBC` с уникальным вектором инициализации (IV).

---

### 3.2. RAG и Управление Базой Знаний (Google File Search Store)
1. **Синхронизация с Google RAG Store**:
   - Единственным источником истины для документов является Google File Search Store.
   - Поддержка создания персональных хранилищ знаний для каждого клиента (`client_store_{userId}`) и отдельного хранилища для каждого бота (`bot_store_{botId}`).
2. **Загрузка и Нормализация Файлов**:
   - Синхронная загрузка и индексация документов в Google Store.
   - Автоматическая нормализация MIME-типов для предотвращения ошибок индексации:
     - PDF: `application/pdf`
     - TXT: `text/plain`
     - HTML: `text/html`
     - Markdown: `text/markdown`
     - CSV: `text/csv`
     - JSON: `application/json`
3. **Система Папок и Тегирования**:
   - Назначение кастомного метатега `folderTag` при загрузке.
   - Иерархия папок: `«Все файлы»` (корневая), `«Общее»`, `«Маркетинг»`, `«Продажи»`, `«Техническое»` + возможность создания пользовательских папок.
4. **Безопасное и Принудительное Удаление Файлов**:
   - Прямой HTTP DELETE запрос к Google Gemini REST API с параметром `?force=true` для принудительного удаления непустых документов (содержащих фрагменты/chunks).
   - Интеллектуальное декодирование URI путей к файлам для корректного удаления из вложенных структур Google Store.

---

### 3.3. Мульти-Ассистентный ИИ-Чат
1. **Управление Ботами / Ассистентами**:
   - Создание, редактирование и удаление ассистентов.
   - Настройка системных инструкций (System Prompt) и персонального базы знаний для каждого бота.
   - Назначение прав доступа клиентам (привязка конкретных пользователей к ботам).
2. **Двойной RAG Поиск (Grounding) и Интеллектуальная Фильтрация**:
   - Ответы генерируются на основе объединения базы знаний бота (`botStoreName`) и собственной базы знаний клиента (`clientStoreName`).
   - **Фильтрация источников по активной Библиотеке пользователя**: Клиентский интерфейс (`App.tsx`) выполняет пересечение заголовков проиндексированных документов Google Gemini с массивом активных файлов пользователя (`files`). Фантомные или удаленные из интерфейса файлы автоматически исключаются из блока источников.
   - **Исключение системных файлов**: Системные и служебные файлы ассистента (`Описание КРБ_ИИ.md`) отфильтровываются и не показываются в пользовательской карточке RAG-источников.
3. **Управление Контекстом, Метки Времени (Timestamps) и Память**:
   - **Гарантированные метки времени**: Пользовательские сообщения сохраняются в SQLite БД **мгновенно** перед отправкой запроса к Google API, предотвращая смещение времени ответа при сетевых задержках Gemini.
   - Отображение точного времени отправки и получения сообщений (`HH:mm`) в чате.
   - Скользящее окно сообщений (Sliding Window size), настраиваемое администратором.
   - Сохранение истории диалогов в базе данных с привязкой к конкретному пользователю и боту.
   - Функция очистки истории диалога (`DELETE /api/chat/history/:botId`) с обратной связью и подтверждением через модальное окно.
4. **Отказоустойчивость и Фоллбек Моделей**:
   - Публичный эндпоинт `/api/health` для автоматического мониторинга доступности сервера.
   - Каскадный вызов моделей Gemini (`gemini-2.0-flash`, `gemini-2.5-flash`).
   - Серверный таймаут (45с) и 3-кратный цикл повторов (retry loop) при сетевых задержках.
   - Информативная обработка квотирования Free Tier (429 RESOURCE_EXHAUSTED) с выводом понятного системного предупреждения.

### 3.4. Системное Логирование и Телеметрия
1. **Файловый Логгер (`server/logs/system.log`)**:
   - Запись сообщений уровня `INFO`, `ERROR`, `DEBUG`.
   - Единый формат: `[YYYY-MM-DDTHH:mm:ss.sssZ] | [LEVEL] | Message | {payload}`.
2. **Клиентская Телеметрия (`/api/logs/client`)**:
   - Автоматическая пересылка действий пользователя и неперехваченных ошибок JS из браузера на сервер для записи в системный лог.
3. **Админ-Интерфейс Просмотра Логов**:
   - Вкладка «Логи системы (Файл)» с интерактивным консольным окном.
   - Фильтрация в реальном времени по выпадающему списку `DropdownSelect`: `Все (ALL)`, `INFO`, `ERROR`, `DEBUG` (`/api/admin/logs?level=...`).
   - Переключатель автообновления каждые 3 секунды + ручная кнопка «Обновить окно».
   - Отключение 304-кэширования HTTP (`Cache-Control: no-store`) для гарантированного отображения свежих записей.
4. **Очистка Логов**:
   - Удаление лог-файла (`DELETE /api/admin/logs`) через центрированное модальное окно подтверждения (`showConfirm`).

### 3.5. Единая Навигация и Дизайн-Система
1. **Стандартизированная Навигационная Шапка**:
   - Единый верхний банер навигации с 3 главными переключателями:
     - **Панель администратора**
     - **Библиотека бизнеса (RAG)**
     - **Чат с ассистентом**
2. **Унифицированная Система Модальных Окон**:
   - Кастомные модальные диалоги `showConfirm` и `showAlert` с размытием заднего фона (backdrop blur), адаптивными кнопками действия и закрытием по клавише Escape.

## 4. База Данных (Схема Prisma)

Key моделей Prisma (`server/prisma/schema.prisma`):
- `User`: учетные записи, роли (`ADMIN`/`CLIENT`), 2FA секрет и статус.
- `UserStore`: привязка пользователя к Google FileSearchStore.
- `Bot`: параметры ИИ-ассистентов, системные промпты, привязанные RAG-сторы.
- `ClientBotAccess`: связи разрешений «Клиент — Бот».
- `ChatMessage`: история диалогов с флагом роли (`user`/`model`) и JSON grounding metadata.
- `ApiKey`: зашифрованные ключи доступа к сторонним сервисам.
- `SystemSettings`: глобальные лимиты, размер скользящего окна контекста.
- `ApiDiagnostics`: журнал задержек и технических ошибок API запросов.

## 5. Обязательный Протокол 3-Уровневой Сквозной Проверки (ABC Protocol)

В проекте зафиксирован и строго соблюдается обязательный 3-уровневый протокол сквозной проверки: `.agents/workflows/testing_protocol.md`.

Любое изменение в коде обязательно валидируется на 3 уровнях:
1. **Уровень A — API & Backend Readiness**:
   - Автоматическая проверка корректности HTTP-статусов (`200 OK`) и JSON-структур backend API (`scripts/full_system_qa.js`).
2. **Уровень B — UI DOM Visibility**:
   - Проверка наличия элементов управления, фильтров, выпадающих списков и кнопок в верстке страницы без CSS-маскирования.
3. **Уровень C — Interactive Behavior (E2E Playwright Browser)**:
   - Симуляция реального пользовательского клика в браузере, проверка реактивности UI и создание видеозаписей/скриншотов подтверждения.
